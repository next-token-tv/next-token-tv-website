## 🎧 本期简介

我们从 DeepSeek Harness 聊起：插件、开源和已有的互联网平台，怎样让一个 Agent 工具长出自己的使用生态？讨论从 Obsidian 插件迁移谈到企业发行版的设想，也聊到“大肥鱼”、美化和启动动画这些看似不以效率为目标的插件。年轻用户的社群、Meme 和自发二创，让我们看到产品传播可能发生在技术圈视野之外；开放生态带来创作空间，也把发现、筛选和治理的问题留给平台与创作者。

接着，我们把话题转向个人 Agent、模型和算力。主 Agent 替人路由任务，能否把不同工具中的资料与成果组织成持续积累的个人上下文？几位主理人分享了跨工具收集信息、整理提示词的实践。我们也谈到推理效率与线性外推的局限，以及数据中心给社区带来的电力、环境和成本压力，以及社区能否获得就业、电费补贴和 AI 服务等收益。安全讨论涉及漏洞发现与钓鱼攻击，也谈到 AI 攻防。对模型变化的判断，需要随新证据更新。

最后，我们聊到软件和游戏网文化：制作门槛降低后，作品供给扩大，争夺发现与分发的竞争也更激烈。上架变容易，不等于获得推荐；功能能跑起来，也不代表游戏好玩或用户愿意留下。游戏开发、个人定制美颜、播客音频处理，以及 Agent 主动寻找素材的例子，都让“人人都能做”变得更具体。许愿式表达和不断调整的使用习惯，可能比预先规定每一步更适合新工具；话题也延伸到创始人参与组织转型，以及 iPad mini、二手 Kindle 和可编程小硬件带来的消费与动手乐趣。

## 💡 本期值得带走的几个问题

**产品怎样在主流技术圈之外找到自己的传播网络？**

我们从“大肥鱼”和插件聊到年轻社群、Meme 与自发二创。讨论的重点不是断言某个传播路径必然成功，而是留意那些主流平台和熟悉的信息圈暂时看不见的兴趣网络。

**人人都能做软件和游戏之后，作品怎样被看见？**

制作成本下降没有消除分发、筛选和体验的门槛。上架变容易，不等于获得推荐；功能能跑起来，也不代表游戏好玩或用户愿意留下。

**Agent 替人调度任务时，个人应该积累什么？**

我们谈到把资料、偏好、提示词和工作成果放进自己能够持续使用的上下文中。工具可以更换，能跨工具调用的个人积累才可能持续产生价值。

**面对快速变化的模型与算力需求，怎样避免过度外推？**

推理效率和递归改进仍处在讨论与验证之中。算力需求也会受模型能力和使用方式影响；用当前观察推算未来时，需要给变化留下空间。

## 🧩 概念解释

- **Harness**：围绕模型组织交互、工具和扩展能力的工作环境。本期主要讨论其插件生态，以及它作为应用与开发基础的可能性。
- **Agent**：能够根据目标调用模型、工具或其他任务流程的软件代理。主 Agent 可以负责理解需求和分配任务，其他 Agent 或工作线程再执行具体工作。
- **个人上下文资产**：个人长期积累的资料、偏好、任务记录与成果，可供不同工具或会话继续使用。节目中的例子包括个人资料库、提示词库和跨工具工作记录。
- **Meme**：便于模仿、改写和再传播的网络表达。本期借“大肥鱼”等例子讨论社群文化如何参与产品传播。
- **网文式的软件与游戏生态**：节目用网文作比，指出软件和游戏的创作门槛正在降低，供给随之扩大；当作品更容易发布，竞争焦点便转向发现、筛选与分发。
- **RSI**：递归自我改进（Recursive Self-Improvement）的缩写。本期将它作为一种可能路径来讨论：AI 如果能持续优化自身的推理能力，进步速度与算力需求的推演都可能发生变化。
- **In the Loop**：让人参与反馈、比较或确认的工作方式。节目举例用盲听比较多个音频处理版本，再由听众反馈选择结果。
