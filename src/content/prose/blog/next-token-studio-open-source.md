几个人围坐在一起录播客，按下录音键之后，还需要知道每个人的声音有没有进来、哪支麦克风对应谁，以及录完以后能不能分别处理这些声音。把整场对话混成一个文件很方便，但后期想单独调低某个人的音量、处理某一路噪声时，独立音轨会留下更多调整空间。

Next Token Studio 现在开源了。这是一款用 SwiftUI 和 AVFoundation 开发的原生 macOS 多轨录音软件，围绕多人播客的录制、回放和素材导出组织功能。项目已经用于 Next Token 多期节目的实际录制，每期约两小时。

源码、中文说明和参与方式都在 [GitHub 仓库](https://github.com/next-token-tv/next-token-studio)。目前运行需要 macOS 14 或以上，应用界面为中文；自行构建需要 Xcode 26 或以上。

## 每路声音单独留下来

选择输入设备后，Studio 将每路输入以设备原始采样率写入独立、同步的单声道 32-bit float WAV。录制过程中可以暂停和继续，各轨实时波形采用相同的幅度比例，方便观察哪一路正在收音、不同麦克风之间的电平差异。

分轨带来的价值，出现在录制之后。假设一场四人对话里，有一支麦克风离说话人特别近，后期可以针对这一轨调整，而不必同时压低其他三个人的声音。它也让素材交接更明确：每路原始声音仍然独立保留，混音可以在后续环节决定。

32-bit float 是保存格式，不能把麦克风或前级已经录坏的声音变回来。录制前仍然需要检查输入设备与电平，监听真实声音。

## 把人和麦克风对应起来

通道编号只说明设备上的输入位置，不能自动说明是谁在说话。Studio 提供主播与麦克风匹配界面：可以借助 macOS Speech 识别中文自我介绍，再手动调整对应关系，按设备和通道保存绑定。

这一步适合开录前确认座位和接线。默认主播名单包含杨攀、歸藏、橘子和向阳乔木，也可以通过工作文件夹中的 JSON 配置修改姓名、头像、别名和颜色。识别自我介绍不等于声纹识别，换设备或改变通道安排时应重新确认。

录音和主播资料保存在本地工作文件夹。语音匹配是独立功能，按 macOS 的选择，匹配音频可能发送到 Apple 的语音识别服务，需要单独授权；正式录音不会在后台自动转写。

## 原始素材和导出文件分开

Studio 默认使用 `~/Documents/Next Token Studio` 保存工作资料，原始录音、主播配置、导出文件和波形缓存各有自己的目录。首次使用时通过文件夹选择器授权访问。

需要继续剪辑时，可以导出无损分轨 WAV 和通道资料；需要试听或分享混音时，可以导出 M4A。M4A 导出采用 AAC-LC、48 kHz、目标 320 kbps，左右声道内容相同，并进行基于 RMS 的响度调整和限幅。它不等同于 LUFS 标准化，发布前仍应结合平台要求检查最终声音。导出不会修改源文件，也可以取消。

长时间录制还需要处理保存和恢复。Studio 会显示已写入、已同步的时长，以及缓冲积压和预计磁盘剩余录制时间；遇到磁盘不足、写入失败或设备中断时报告问题。恢复流程保留原文件，另外创建各轨对齐的恢复副本。检查点和恢复机制提供了一条找回素材的路径，但不意味着任何故障都不会丢失音频，重要录制仍需要备份安排。

## 从源码开始使用和参与

这次开放的是源码。公开仓库并不代表已经提供官方签名、公证的安装包。开发者可以打开 `next-token-studio.xcodeproj`，按照仓库说明选择自己的开发团队和 Bundle ID，构建后确认麦克风权限、工作文件夹访问及实际设备表现。

仓库同时提供自动化检查，覆盖多轨音频、回放、导出和恢复等环节。实际录制经验与这些检查各有作用：离线测试能反复验证文件和异常处理，具体声卡、麦克风与系统组合仍需要实录确认。

代码、测试、脚本和文档采用 **AGPL-3.0-only**，以仓库许可证及版权说明为准；Next Token 品牌和四位主理人的头像不包含在这项代码许可中。

如果你也在制作多人播客，欢迎从自己的录制设备和素材流转方式出发试用。反馈问题时，附上系统版本、输入设备、通道数量和复现步骤，会比一句录音失败更有助于定位。也欢迎通过仓库参与改进，让下一次录制少一些临场排查，多留下一份可以安心交给后期的素材。
