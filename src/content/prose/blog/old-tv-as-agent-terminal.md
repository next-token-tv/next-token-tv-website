电视上只常用两个 App，首页却塞满内容，每次打开都要按一串遥控器。第七期的启动器改造从这里开始：参考已有项目，按自己的使用习惯改一个首页。

这个需求不复杂，却很适合拿来检验 AI 做出来的界面。改完以后能否少按几下，家里其他人会不会用，坐在沙发上看不看得清，都有具体的答案。

## 先拿遥控器走一遍

手机界面可以直接点击，电视往往靠方向键逐个移动焦点。常用 App 放在哪里、默认选中哪一个、按返回会去哪儿，比屏幕上能放多少张卡片更影响使用。

Android 的[电视导航指南](https://developer.android.com/training/tv/get-started/navigation)强调较短的导航路径，以及用方向键访问所有可见控件。检查时可以从开机开始，一直走到播放内容，再退回首页。只要中间某个弹窗无法用遥控器关闭，这套路径就还没走通。

简化首页可以先只放常用入口。需要搜索、最近观看或其他功能时，再看看增加它会不会挤远原来的按钮。每加一个入口，都应重新用遥控器试一次。

## 旧设备的问题要分开查

节目中还有一台电视，经常提示内存不足，虽然没有新增多少 App。仅凭这段描述无法判断原因，也不知道提示具体指向运行内存还是存储空间。

更换启动器能够改变首页，但未必解决这类问题。如果应用本身打不开、播放卡顿或系统提示空间不足，需要查看对应错误和设备状态。首页看起来更轻快，不能代替这些检查。

改造前保留原来的恢复入口也很有用。新首页有问题时，能够回到设置或原启动器，就不至于为了一个界面实验影响日常看电视。

## 把 Agent 放到电视上，要多处理哪些事

录制时，歸藏已经接入了 Codex 的电视入口，Grok Bot 的切换入口还在制作。检索节目、控制其他 App、定时播放早报，是接着提出的想法。

模型和任务可以运行在另一台设备上，电视负责显示与输入。于是需要验证的事情也很具体：从沙发上读一段回复是否费劲，语音输入后有没有明确反馈，网络断开时页面会不会一直显示处理中。

共享屏幕还有显示范围的问题。个人工作会话如果直接搬到客厅，家人看电视时可能看到私人消息。为电视单独提供一个只显示选定任务的入口，会比照搬整个桌面更容易管理。

至于打开其他 App、模拟按键或唤醒电视，需要逐项确认设备支持。节目提到的 ADB 是 Android 调试工具，[官方文档](https://developer.android.com/tools/adb)列出了调试连接的启用与授权条件；设备在同一局域网内，并不足以保证任何控制都能执行。

可以先把常用 App 首页做稳，再加一个查看 Agent 结果的页面；遇到无法返回或失去焦点的地方，先修好遥控器导航。
