想在产品里用上一个多模态模型，先要在文档的汪洋大海里找到模型名称，再弄清调用方式；好不容易接通，首字延迟却能达到别家的一百倍量级——这是录制时一次真实对接的经历。买到了 Token，和把 Token 变成体验之间，隔着一整段工程。利润空间的问题，正藏在这段距离里。

## 转售的账算不过来

最直接的商业想象是转售：拿到折扣价，加价卖出。现实是折扣很薄。录制时有人接到报价：八折转售主流模型的 API。做生意的基本线是四成毛利，两成的差价意味着每做一单赔一单；头部模型的官方渠道自己就能给出折扣，中间商没有任何空间。模型供不应求时更是如此——没有富余产能，厂商就不需要给折扣。

另一种常见的账面处理是预收：把一年套餐的钱一次收齐，放进当期报表。这叫现金流，不叫利润——服务还没交付，成本还在后面。把这些数字当成盈利能力，是那段时间应用层融资故事里常见的误区。市场资金又在向少数赛道集中，靠融资补贴亏损的余地变小，利润问题于是无法回避。

## 模型便宜之后，才腾出毛利

转机来自供给侧。录制前后的一批低价、高速模型，第一次给了应用层像样的价差空间：同样是完成一次回复、一次判断，成本降到原来的零头，服务定价就有了回旋余地。讨论里转述过一个案例：一家企业服务公司过去每收到一美元收入，要向模型厂商支付更高的成本，换成基于开源模型自训的版本之后，毛利率才转正。这是转述的口径，未经独立核实，但机制是清楚的：模型支出大到吞噬毛利时，应用公司挣的钱其实一直在替模型厂商打工。

这也是"不要羞于卖 Token"这句话的上下文。应用层做的所有工程——界面、缓存、调度、验证——最终都是为了用户愿意在这里消耗 Token。承认这一点，才能算清自己到底挣哪一段钱。

## Token 是计量单位，不是产品

把 Token 比作货币的说法在录制时很流行：模型能力成了数字世界的硬通货，连支付公司收购模型路由平台，都被解读为提前布局"Token 结算"。这个比喻有解释力，但也容易误导——货币的价值在于通用，而应用层的价值恰恰在于不通用。

用户付钱买的从来不是 Token 本身，而是 Token 背后的确定性：可用性、延迟、输出格式、出错时的兜底，以及结果可以放心交给下一步的保证。同样的 Token，从云厂商的控制台里取，和从一个顺手的产品里取，体验完全不同。云厂商按 to B 的方式卖接口，使用者却常常只是想让它跑起来——这个落差就是机会。

## 挣的是"最后一段距离"的钱

于是出现了所谓体验套利：把难接的模型接好，把难调的参数调顺，让用户和 Agent 可以直接调用。多模态和内容生产类模型尤其明显——能力强，接口却散落在各自的文档里，谁把它们组装成顺手的服务，谁就在挣工程与体验的钱。这个位置不缺尝试者，缺的是把接口服务本身当产品做的人；讨论里被看好的方向，是覆盖视频、图像等一整类多模态模型的一站式接口，恰恰因为那部分最难读、最费力。这类机会不需要独家模型，只需要把"能用"变成"好用"的那段距离。

成本结构还在变化。推理成本在下降，而 Agent 规模化运行所需的算力硬件反而在涨价，自建与租用的账随价格实时改写。不变的是位置：单纯转售折扣的业务没有护城河，利润属于那些把 Token 变成确定服务的人。模型越便宜，这段距离的价值越清楚——它才是应用层真正的毛利来源。
