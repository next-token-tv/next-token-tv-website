几百本书已经加入微信读书书架，却一直没有认真分组。一次整理把书目拉到本地，让 Agent 提出分类，由用户确认后，再通过 Computer Use 操作 Mac 上的应用，把书一本本放回相应分组。按这次使用记录，一个多小时后，书架整理完成。

这件事很快引出争论：排好之后会怎么看？如果并没有因此多读一本书，算不算假提效？另一种理解则简单得多——这就是一次收纳。

两个判断看似冲突，其实在衡量不同的结果。一个要求整理带来后续产出，另一个把恢复秩序本身当作想完成的事。

## 先分清这一小时换来了什么

这次任务明确完成的是分类与归位。它没有提供整理前后的找书时间，也没有记录后续阅读量，更没有证明省下了多少人工小时。把一个多小时的执行时间写成节省一个多小时，会偷换比较对象：如果用户原本不会亲自整理，就不存在同等长度的人工工作被替代。

但原本不会做，不代表不值得做。很多个人事务长期搁置，并非毫无意义，只是它们的价值不足以抵消当时的执行成本。工具降低成本后，重新整理书架、把收藏汇总成清单，都可能进入愿意尝试的范围。

这里新增的价值，是以前没有得到的结果。它可以有用，也可以只是让人满意；两者都需要与成本比较，却不必被强行换算成工作效率。

## 分类应该贴近下一次使用

书架可以按学科、作者、阅读进度分类，也可以按当前正在研究的问题分类。这些方式没有脱离用途的优劣。一个准备写文章的人，与一个想找周末读物的人，可能需要完全不同的入口。

个人信息管理研究长期关注的，正是已经保存的东西如何回到日常活动里。William Jones 在 Keeping Found Things Found 项目的介绍中，把有效的信息管理与日常规划联系起来。这个视角提供了一种提醒：分类系统的意义可以从未来要做的事情反推，而不只是追求目录看起来整齐。

假设某人正在研究城市生活，一本建筑史和一本小说可能值得放在同一组；若严格按出版分类分开，反而增加来回寻找的步骤。反过来，如果用途只是浏览全部藏书，一个稳定、简单的学科分类也可能足够。

Agent 可以降低提出分类方案的成本，用户仍然需要认得这些类别。一个机器解释得很完整、自己下次却想不起来的体系，很难成为长期入口。

## 收纳有终点，整理也可能成为拖延

把收纳的愉悦承认为价值，并不意味着所有整理都值得继续。分类刚完成，又想统一封面、补齐简介、打上多层标签，接着做阅读计划，一项原本有限的任务可以不断扩张。

若目标就是把混乱书架整理到看着舒服，达到这个状态便可以结束。若目标是更方便阅读，则值得回到真正的使用：需要一本书时能不能找到，刚买的书能不能轻松归位，分类是否还需要经常重做。

这些问题可以在后续使用中回答，无需为了证明提效再建一套复杂仪表盘。挑几个真实的找书场景观察，就比统计新增了多少标签更接近目标。

一次整理若只是带来满足感，也可以如实把它称为整理。真正需要警惕的，是不断扩大的准备工作挤占了原本想做的事，却始终用效率来解释。

## 个人 Agent 不必只做能写进周报的事

商业工具常用节省工时和增加收入解释价值。个人生活里还有兴趣、舒适、秩序感与探索，它们未必对应产出指标。花时间做一张个人书单，与花时间摆放实体书一样，可以由使用者自己的偏好决定。

不过，这种价值也不能替产品免去检验。一次让人开心的整理，是否足以支撑长期订阅，是另一回事；分类完成的瞬间好看，也不能证明此后仍有用。单次满足和持续使用应分别观察。

对这次书架整理，最准确的结论仍然具体：用户完成了一项想做的收纳工作，后续阅读收益尚未被记录。个人 Agent 的价值可以从这里开始，无需先把每一种生活愿望包装成生产力。
