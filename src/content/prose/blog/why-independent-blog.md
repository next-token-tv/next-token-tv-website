整理一套 AI 信源时会出现一个明显的断层：海外主要的 AI 媒体、播客、公司博客和产品发布页几乎都提供 RSS；国内厂商的官方新闻和产品 Release Notes 普遍没有。有的更新甚至把日期写进标题，正文里连一个时间戳都找不到。对订阅器和自动化工具来说，这是两种完全不同的互联网。

这种差别不是技术能力问题。RSS 阅读器在中文互联网也曾经流行过，[抓虾](/wiki/products/zhuaxia)一类的阅读器兴盛一时，后来这一层开放基建被平台竞争消化掉了：内容各自圈进自己的 App，订阅失去了位置。微信公众平台的机制是一个典型——它提供原创保护，发布后别人不能照搬，在一个洗稿成本极低的环境里，这套封闭设计有现实的原因。代价是公众号内容几乎不向站外开放：做 RSS 订阅器的人遇到的最大障碍就是公众号无法订阅，想公开提供抓取服务还会带来合规问题。

## 独立博客过去输在哪里

从读者经济的角度看，独立博客长期处于下风，而且输得有结构上的原因。过去的读者经平台推荐流分发，独立网页没有自己的分发渠道，只能在搜索结果里排队；公众号背后是国内自媒体最成熟的盈利来源，而开放订阅一直没有找到自己的变现方式——[Substack](/wiki/products/substack) 一类靠 RSS 与邮件订阅的 Newsletter 是少数例外。开放在没有商业支撑的情况下收缩，是上一轮竞争的实际结果。

[袁朝发](/wiki/people/yuan-chaofa)的对比可以当作一个样本：他长期同时运营独立博客和公众号，同样一篇文章，独立博客的阅读量远不如公众号，于是难免怀疑，辛苦维护独立博客是否还不如只发公众号。如果读者只有人类，这个结论很难反驳。

## Agent 成为新读者

Agent 的出现给这个问题加了一个变量，它改变了"没有分发渠道"这个前提。Agent 找内容不靠推荐流，只看内容是否可达：一个被反复提到的观察是，让 Agent 查某位只在公众号写作的作者的文章并总结风格，它找不到；换一位有独立博客的作者，它把整个博客读了一遍，风格判断也更有依据。原因不复杂——公众号内容在站外几乎不可检索，而开放网页可以被 Agent 抓取和阅读。Agent 一直在扫描开放内容，这件事不需要人类读者在场也会发生。

"让互联网和 Agent 认识我"，说的就是这种变化：开放的内容多了一批不需要人工操作的读者，它们不参加推荐流的分配，只认地址和格式。

需要说明的是，这目前还是个别的观察，不构成对流量效果的承诺。独立博客在搜索引擎排序中的位置没有因此改变，各家 Agent 如何索引和引用开放内容也仍在变化。把开放网页当成确定性的"AI 流量入口"，超出了现有材料能支持的范围；目前能确认的只是，开放的内容可被读取，封闭的内容连被找到的机会都没有。

## 用什么形式开放

如果接受"内容应该让 Agent 读到"这个前提，接下来的问题是形式。RSS 仍然是一个低成本的答案：它只是放在那里，任何订阅器或 Agent 都可以自己发现和读取。相比之下，把信源包装成一个 MCP 服务，反而要求使用者先完成安装，多了一道门槛。另一个设想是走公众号 API，把自己授权发布的内容自动同步成一份 RSS——这属于讨论中的方案，能否稳定实现取决于平台接口，不能当成现成能力。

无论选择哪种形式，边界都应该放在自己有权发布的内容上。发布在平台内的内容受平台机制约束，替别人把封闭内容转成开放订阅，超出了个人创作者该做的范围。本站的做法是把内容放在开放网页上：每期节目提供网页版和 Markdown 格式的文字稿，段落带稳定锚点，方便人和 Agent 引用；博客文章同样提供 Markdown 版本。这些都是站点自己有权发布的内容，开放的成本可控。

## 开放能否获得回报

开放内容在商业上能否成立，上一代互联网没有给出肯定答案：Web 2.0 时代同样有 RSS 标准和订阅习惯，最终因为没有赚起来而退场。这一代是否会不同——新一代更开放的创作者和服务能不能吃到某种红利——是一个还没有答案的问题。

对个人创作者而言，可计算的部分是：在自己有权发布的范围内维护一份开放网页，边际成本不高，而且它同时服务人类读者和 Agent 两类读取者。不可计算的部分是回报。给内容加一份 RSS 的倡议是否会被广泛响应、开放是否会在 Agent 时代重新变得划算，只能留给之后验证。
