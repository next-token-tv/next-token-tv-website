一个任务看起来很适合交给 AI 团队：抓取 GitHub Trending 和 Product Hunt 的热榜，整理成内容，再接上语音合成，做成持续播放的播客。

几个 Bot 很快商量出方案。分工明确，彼此通知修改，版本不断增加。旁观这场讨论，会觉得工作已经有条不紊地推进；真正等到执行，却发现耗时很长，Token 也消耗得很快。这是一次使用中的观察，材料没有给出完整耗时和账单，但它足以提出一个问题：群里越来越热闹时，离成品究竟更近了多少？

## 给角色起名字，比划清任务容易

把技术、产品、营销角色拉进同一个群，很容易获得组织起来的感觉。每个角色都有立场，能够补充意见，也能对其他人的方案提出异议。在产品脑暴里，这种互动确实可能帮助使用者发现自己没有想到的角度。

不过，角色的差异不自动变成执行上的独立性。一个营销 Bot 可以评价标题，一个产品 Bot 也可以评价标题，第三个 Bot 再总结双方意见。如果没有人拥有定稿权，意见越多，标题越难结束。

热榜播客的工作可以按对象拆分：两路信息分别采集，编辑负责选题和脚本，语音环节接收定稿。这样的划分提供了输入和输出的边界。按照职位搭一套组织，则可能让每个角色都参与每个环节，工作从制作内容变成持续讨论如何制作内容。

判断分工是否有效，可以先问一个具体问题：某个 Bot 交回什么东西之后，这一步就算结束？如果答案仍是参与讨论，任务就没有真正被分出去。

## 并行收益取决于任务之间要等多少次

两路热榜采集可以同时开始；配音需要等待脚本，最终混音又要等待音频。增加执行者，能够缩短独立工作的等待，却无法消除本来就存在的前后依赖。

更麻烦的是人为增加的依赖。假设脚本写完后，五个角色必须逐一同意才能进入配音，那么系统就多出五次沟通机会。任何一次提出新要求，都可能把前面的工作重新打开。这里描述的是一种可能的设计，并不是对那次试验内部实现的断言。

Anthropic 在 2025 年公布的多 Agent 研究系统经验里，也把可并行性作为重要条件：独立方向的广泛检索适合分给子 Agent；大量共享上下文、相互依赖的任务则更难受益。该团队报告，多 Agent 系统在其数据中约消耗普通聊天十五倍的 Token。比较基准是聊天，并非所有单 Agent 工作流；这个数字不能直接套到任何产品账单上。

这份经验支持的判断很有限，也很实用：多 Agent 能购买更多探索容量，但需要足够有价值、可以独立展开的工作来消化它。

## 脑暴和交付可以采用不同的组织方式

脑暴阶段不必急着消灭所有重复。让几个角色分别挑毛病，有时就是为了延迟收敛，找出被忽略的可能性。使用者从不同视角里获得灵感，也是这一阶段可以接受的结果。

进入交付阶段后，目标变了。谁决定采用哪版方案，谁可以修改已确认的要求，哪些问题需要退回用户，都应该收紧。继续保留一个人人都能随时改方向的群聊，会把探索阶段的开放性带进本应执行的阶段。

一个可尝试的安排是让讨论有终点：先收集若干不同方案，再由明确的负责人定稿；后续执行者可以报告阻碍，但不因个人偏好重开全部讨论。这样的安排仍然允许分工，只是让分工围绕产物推进。

## 管理一支 AI 团队的快乐，也可以单独成立

角色扮演的乐趣无需伪装成生产力。看不同性格的 Bot 讨论产品、接住一个突然冒出的点子，本身可以是一种娱乐和创作体验。只要使用者愿意为此付出时间与费用，它就有自己的价值。

容易混淆的地方，是把团队的存在感当成交付能力。头像多、发言密、方案整齐，都不足以说明任务完成得更好。若目标是做出一档播客，值得比较的是相同要求下，成品质量、等待时间、费用和人工介入次数如何变化。

组织结构可以很轻。只有在某一块工作值得独立展开、结果可以清楚交接时，再增加一个执行者。让一个 Bot 留在前台回应用户、另一个在后台处理长任务，也是一种明确的分工；它的价值不需要靠一场全员会议证明。
