一台 512GB 的笔记本，换成 2TB 的新机，三个月后一看，1TB 已经没了。这不是下了多少电影，而是 Vibe Coding 改变了生产速率：项目、Worktree、生成的素材和中间产物，以前所未有的速度往硬盘里堆。账单变了，值得算清楚它由哪些部分组成。

## 空间被谁吃掉了

被吃掉的空间里，相当一部分可以再生。终端里每次装包留下的安装包和依赖、Agent 反复操作浏览器积累的缓存——一次观察中，仅 [Chrome](/wiki/products/chrome) 的缓存就达到 60GB 以上；自带浏览器的聊天办公软件各有类似的堆积。这些东西删了会再生成，占的却是最显眼的地方。

另一部分难以再生。做开发的人对系统镜像不陌生：为了在多个系统版本上测试，几套 iOS 和 iPadOS 镜像加起来就是四五十GB，[Xcode](/wiki/products/xcode) 本身也不小；聊天工具的本地数据动辄是单项最大——不少人的第一大头是[微信](/wiki/products/wechat)。还有 Worktree 和疯狂生成的项目文件，这正是 Vibe Coding 带来的新变量：以前一个月开不了几个项目，现在一天可以并行一堆。

这些数字都来自个人机器上的观察，不是统计结论，不同用法差异极大。但方向是共同的：单机容量从"够用很多年"变成"每年都要重新规划"。

## 缓存可以删，底稿不能删

对待这些数据不能一把抓。缓存、安装包属于可再生数据，删掉的代价只是重新下载；项目文件和记录属于难以再生的原创数据，删了就没了。

麻烦的是中间地带。做内容的人最清楚：录 10 到 20 分钟的原始视频，按录制规格就是 20 到 30GB。这些底稿"删也不行，不删也不是"——重做成本太高，留着又持续占空间，只能先放着，过段时间再决定。一块硬盘里，可再生与不可再生的数据混在一起，这正是清理变难的原因。

自动清理的风险已经显现：让 Agent"恢复 100GB 以上空间"，它逐个目录找，确实清出来了，代价是几乎所有常用软件都被删掉，最后只好彻底重装。容量焦虑之下，"一键清理"听起来诱人，但区分哪些文件还能再生、哪些是孤本，目前仍是人要做的判断——本文也不提供任何未经复核的清理操作。

## 存储要分层

既然数据性质不同，存放方式就该分层。

最上面一层是本地热数据：正在跑的项目、频繁改动的文件，留在速度最快的 SSD 上。往下一层是家庭归档：不天天动、但时常要查的东西，放到 NAS——局域网直接访问，延迟不是问题。已经有人在把本地 Memory 挂载同步到 NAS，让个人数据在家里有一份集中存放。

再往下是冷归档：视频底稿这类"肯定不想丢、但一年也取不了几次"的数据。冷存储的设想是：价格比常规网盘低一个量级，代价是不能马上下载——想取回某个卷，发一个请求，等上一天。价格差十倍换等待时间，听起来成立；反对意见同样直接：多数用户连 24 秒都不愿意等，等待会直接杀死需求。这个设想至今仍是设想，没有一个已验证的产品摆在货架上。物理介质的老办法也有局限：一张 DVD 只有不到 7GB，连一期节目的量都装不下。

## 容量之外的账：备份与找回

硬盘账单不止容量一项。要备份就意味着至少两份：家里买 NAS，硬盘可能坏，做备份就得再买一块盘，成本接近翻倍；用云订阅则按月付费——一个录制时的个例是全家 2TB 的 [iCloud](/wiki/products/icloud) 套餐接近用满，再往上一档，每月开销要涨两倍多。这只是个人的账单，不构成对任何人的预算建议。

还有一项更容易被忽略：找得回来。多机器时代，文件开始散落在更多地方——克隆进云电脑虚拟机的工具和产出、交给 Agent 处理的冷备份。把每期节目的冷备份交给 Agent 之后，一个现实的问题是：备份到底落在哪个目录，交托的人并不清楚。存下来了，不等于管得起来；需要恢复的那一刻才发现说不清路径，备份的价值就要打折扣。高频自动同步同样有代价，已有把硬盘读写用到报废的个例。

分层因此不只是省钱，更是风险管理：不可再生的数据放在更稳、有冗余的地方，可再生的数据不占昂贵的地方。至于那些"删也不行、不删也不是"的底稿，真正的答案可能不是更大的硬盘，而是一个取回慢一点也无所谓、便宜得多的去处——它现在还不存在，但需求已经先到了。
