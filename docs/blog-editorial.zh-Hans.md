# 博客编辑规范

## 内容定位

Next Token 博客以节目中的话题、观点、案例或一句值得追问的表述为起点，结合独立研究与分析，写成可独立阅读的主题文章。正文直接解释问题、展开案例、建立论证；读者不需要认识主理人，也不需要先听完整期节目。

文章以读者问题为单位。一期可以产生多篇，也可以只写一篇；不同主题不强行统一，同一问题的多个角度不机械拆分。篇数、字数、章节数和引语比例均不设固定配额。

## 从话题到文章

节目提供选题线索，也可以提供案例与观点；文章的材料范围和论证深度不受节目讨论时长限制。简短提及的话题也可以独立成文，新增研究可以成为正文的主要部分，不设节目内容与外部材料的比例。

延展围绕一个明确的读者问题，可以补充概念解释、历史背景、技术原理、外部案例、比较、反例和实际验证，形成节目里尚未展开的分析。选题价值取决于问题是否值得回答、能否找到可靠材料，不因文字稿篇幅短就降级，也不用无关知识凑篇幅。

节目原有内容、外部证据和编辑分析各有归属。节目链接只能支持其中实际出现的说法；新增事实引用相应来源，推论交代依据与适用条件。独立研究可以修正节目里的初步判断，不能把新增结论写成主理人的原意、共识或亲历。假设例子须表明是假设，实际测试须有真实记录。

选题计划应分别列出节目切入点、拟延展的问题、资料或验证需求。研究型文章与案例型文章都可以优先安排；需要研究是任务范围，不是暂缓理由。主题过宽、缺少可行证据路径或与其他文章重复时，再收窄、合并或暂缓。

## 叙述视角

文章采用稳定的编辑叙述视角，以产品、问题、任务和现象作为主语。

- 不用“杨攀说”“歸藏认为”“橘子接着提到”等发言人串联段落。
- 不用“有人指出”“某位主理人认为”替代姓名，继续保留会议纪要结构。
- 不按“随后聊到”“圆桌最后讨论”“这一期留下的问题”等节目顺序推进正文。
- 不冒用“我”“我们”把他人的经历写成作者亲历，也不把某个人的判断改成全体共识。
- 人物身份确实是主题的一部分，或直接引语必须署名时，可以保留人名；不为消除所有姓名而损害事实归属。

去掉姓名只是表层变化。文章结构必须按问题的逻辑重组，不能把逐段转述简单改为无主语的断言。

## 文章结构

标题明确主题和文章要解释的问题，不要求复用节目标题或包含期号。摘要说明阅读价值，不介绍谁参加了讨论。

标题句式根据内容选择，可以直接表达观点、呈现场景、点出矛盾，或描述一个具体案例。问句用于确实值得展开、正文能够回答的问题，不作为默认的吸引点击模板。同批选题和栏目列表应避免连续使用“为什么”“如何”“能不能”等相同句式；不设问句比例，也不靠删掉问号伪装成陈述句。改为陈述句时，结论的确定程度不能超过材料支持的范围。

开篇从具体需求、场景、矛盾或案例进入主题，不以节目介绍和参与者名单开场。小标题承担问题的不同部分，段落之间有逻辑联系，不按发言轮次切分。

正文可以结合节目与外部材料建立论证，形成独立的、有依据的分析。事实、案例与推论的确定程度须相符；推论不能伪装成测试结果或原说话人的表态。

结尾落在文章已经展开的判断、适用条件或仍待回答的具体问题上，不回顾节目流程，不追加空泛的行业展望和人物态度。

## 案例与事实边界

个人经验可写成“一次试用”“一项试验”或具体场景，通过文末原文链接保留可追溯归属。保留决定案例意义的输入、规模、方法、结果与限制，不把个例升级为普遍规律。

- 三百多条记忆筛出约十八条，是一次筛选结果，不能写成最优记忆数量。
- 一万名好友的任务在素材记录时尚未完成，就不能补出完整耗时、准确率或模型排名。
- 希望标签页与项目联动，是产品设计设想，不能写成已经发布的能力。
- 更宽的屏幕可能适合某种布局，不能据此写成使用 Agent 的硬件门槛。

保留有价值的数字、产品细节、具体操作和分歧。限制条件在影响判断的地方说明，不在每段重复免责声明。

涉及录制时的产品状态，时间背景由页面来源信息交代；正文不暗示这些状态一直延续至今。新增的外部事实需有独立来源，与节目中的体验和观点区分。

## 语言与引用

使用自然、具体的书面表达。术语在帮助理解时保留并解释，不以抽象总结替换真实细节。避免机械对举、段段下结论、无内容的小标题、重复导语和替人物描述心理或语气。

直接引语只在原措辞确有价值时使用，必须核对原文与归属。清理、拼接或重写过的句子不加引号。

正文可保留帮助理解的 Wiki 链接。节目出处主要由页面元信息和文末“相关资料”承担；关键材料链接到稳定文字稿段落，链接名称描述内容，避免每段插入“回到这段讨论”。外部研究资料同样列入文末来源；关键数字、争议事实和直接引语按需就近引用，不把整篇文章的证据都归给节目。若某条归属会改变读者对观点的理解，应就近交代。

页面和文章只呈现内容、来源与必要的状态，不展示内部选题账本、写作流程、工具评分或审校过程。

## 写法对照

| 对谈整理式表达 | 主题文章表达 |
| --- | --- |
| 橘子说他让 Jev 给三百多条记忆打分。 | 一次针对 Cola 的试用，把三百多条记忆交给 Jev 打分。 |
| 杨攀认为 Jev 更适合海量高频的场景。 | 单次调用的时间和成本，会在大量重复判断中积累成可感知的差异。 |
| 歸藏接着说，他希望标签页和项目联动。 | 如果一项工作已经有自己的项目和会话，相关网页也值得围绕这项工作组织。 |

这些例子只说明表达方式。改写仍须有原始材料支持，并保留试验进度、推论性质和产品状态。
