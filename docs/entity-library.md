# 资料库实体分类

## 品牌、产品与节目

品牌条目介绍公司、组织、独立媒体或社区品牌。产品条目介绍用户使用的模型、应用、平台、开发工具和开源项目。节目使用 `shows` 条目。

产品的 `brand` 为可选字段。公司官网、团队介绍、创始人或法律主体的存在，本身不构成另建品牌条目的理由。只有资料库独立介绍该组织，例如其多条产品线或组织层面的内容，才分别收录公司与产品。同名公司和模型可以分别收录，但摘要、类型和关系必须明确各自含义。

| 实体 | 收录方式 |
| --- | --- |
| OpenAI、Anthropic、Apple | 品牌，关联各自产品 |
| DeepSeek、MiniMax | 公司与模型家族分开收录 |
| Herdr、Three.js、Pi、Dia | 只收录产品，不添加重复的项目品牌 |
| Runta、OpenRouter、fal.ai、X | 只收录平台产品 |
| Qwen、混元、WorkBuddy | 只收录对应模型或应用产品 |
| SpaceXAI | 品牌；xAI、X.AI 为别名，与 X 平台分开 |
| WaytoAGI | 社区品牌，分类为 `community-brand` |
| Y Combinator | 品牌使用全称，YC 为别名 |
| 豆包 / Doubao | 按品牌收录，关联 Doubao Seed 模型家族与豆包工作产品 |
| Next Token Weekly | Next Token 旗下节目，链接 `/weekly/`，不重复收录为品牌 |

独立基金会和其维护的开源产品可以分别收录。人物与产品可直接建立关系，不要求通过品牌中转。

## 产品分类

产品按主要用途分类。Agent 产品即使开源，也归入 `agent`，包括 ZCode、DeepSeek Harness、OpenClaw 与 Hermes Agent。

操作系统使用独立分类 `operating-system`，包括 iOS、macOS、Linux 与 Omarchy；Linux 的摘要明确其内核与系统生态范围。

## 模型、名称与别名

模型家族保留不带版本号的主条目。带版本号、日期或快照后缀的名称，以及这些版本已有的有效别名，归入对应模型家族的 `aliases`，不单独生成产品页。版本名称在逐字稿中保持原文，链接指向模型家族。

Muse Voice Transcribe 归入 Muse 模型家族的别名，不单独生成产品页。

主名称使用正式名称，不额外添加“项目”等分类后缀。Next Token 的完整名称、Next Token 和词元之外指向同一品牌。别名只收录确实指向该实体的名称；套餐价格或口头描述不作为别名，Codex 200 不属于 Codex 别名。

含有产品名称的作者描述不作为人物别名，例如“Ruby on Rails 那个连，作者”中仅产品名称建立链接。作者身份由人物与产品的资料关系表达。“豆包办公”属于逐字稿中讨论的误称，不登记为豆包工作的正式别名。

实体使用稳定 ID，引用与页面路径不从展示名称临时推导。实体合并或分类迁移时，分期提及、人物关系和逐字稿链接使用最终实体；导入快照由脚本生成。歧义名称由分期规则明确指定，不靠分类优先级猜测。

## 资料字段

硬件条目既可以表示具体产品，也可以表示明确的产品系列。只泛指“群晖 NAS”“绿联 NAS”时，以该名称收录 `hardware` 产品系列，摘要明确其系列范围，不推断具体型号，不填写统一的盘位、配置或发布日期。没有独立组织内容时无需另建公司条目；已有品牌条目的产品可引用它，例如 Xiaomi 智能存储引用小米。

泛称“NAS”不作为某个厂商系列的别名。只有特定分期语境中，“群晖”“绿联”等厂商简称明确代指 NAS 时，才在该分期的 `scopedAliases` 中关联产品系列，不写成全局产品别名。

条目包含中英文名称与摘要、明确的类型、官方链接和核验日期；事实来源保存于 `sources`。产品状态、发布日期和所属品牌仅在有依据时填写。资料说明记录当前分类规则与事实，不记录讨论或操作过程。
