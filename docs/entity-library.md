# 资料库实体分类

## 品牌、产品与节目

品牌是提供者，产品是被提供、被使用的具体对象。分类以条目实际指代的对象为准，不以名称、知名度、官网、商标或“平台”等宣传用语决定。

### 判断顺序

1. 名称明确指公司或组织，条目介绍谁在提供服务及其业务、团队和旗下产品，收录为品牌。
2. 名称指用户可以使用、安装、调用或部署的具体软件、模型、工具、硬件或在线服务，收录为产品。运行时也是产品，不因拥有独立社区或商标而归为品牌。
3. 名称同时用于公司和产品时，默认收录产品；只有需要独立介绍公司主体时，才另建品牌。
4. 简称、版本名或不同拼写作为对应实体的别名，不重复建条目。版本模型名称遵循下文的模型家族规则。

### 同名品牌与产品的拆分条件

只有能分别写出有来源支持、内容不重复的介绍时，才同时建立品牌与产品：品牌介绍组织主体、业务及旗下产品关系；产品介绍用途、功能、使用方式和适用场景。如果两份介绍基本重复，就不拆分。公司官网、团队介绍、创始人或法律主体的存在，本身不构成另建品牌条目的理由。

产品的 `brand` 为可选字段；仅在所属关系有依据时填写。独立产品不要求补建品牌。公司与同名模型可以分开收录，但摘要、正文、类型和所属关系必须明确各自含义。

### 内容与分类一致性

品牌条目以组织及业务为主，可概述旗下服务；不能仅将类型改为品牌，却仍以套餐、价格、API 接入和功能操作为正文主体。产品条目则以具体使用对象为主。“平台”只描述服务形式，不能单独决定实体类型。

Fireworks AI、硅基流动的品牌条目介绍公司主体及业务；两者的具体推理服务属于产品层面的对象。业务相似不意味着可以混用公司与服务的概念。Adobe 是品牌，Premiere Pro、After Effects 是产品。节目运营数据仍使用 `shows` 条目。

## 品牌分类与平台产品

公司与组织按资料库主要介绍的业务分为人工智能、硬件与半导体、互联网与软件服务和其他。媒体与社区统一归入 `media-community-brand`，基金会、加速器与音乐公司目前归入其他。跨领域组织按主要介绍的业务归类，其他业务保留在摘要中；不再使用公司品牌或开源品牌作为分类。AWS、阿里云、腾讯云与火山引擎统一归入互联网与软件服务 `internet-software-brand`，不单设云服务分类。品牌库不使用“平台品牌”分类。

用户直接使用的平台收录为 `platform` 产品，包括哔哩哔哩、Spotify、闲鱼、小红书、小宇宙、微信、飞书、YouTube、OpenRouter 与 fal.ai。Hugging Face 按人工智能品牌收录。同名组织与平台仅在各自有独立介绍内容时分别建条目。

## 产品分类

产品按主要用途分类，不设“开源项目”分类。开源是产品属性，保留在摘要和官方仓库资料中。Blender 归入应用，FFmpeg 与 Godot Engine 归入开发者工具，T3 Code 归入 Agent。Agent 产品即使开源，也归入 `agent`，包括 ZCode、DeepSeek Harness、OpenClaw 与 Hermes Agent。Cherry Studio、豆包工作、CodePilot 与 LibTV 按任务执行和 Agent 工作流归入 Agent；仅内置 AI 功能、面向问答或提供单项生成能力的应用不因此自动改类。

开发者工具 `developer-tool` 包括主要用于构建、调试、测试软件或管理软件研发流程的产品。ColaMD 与 Linear 归入开发者工具。

闪电说作为语音输入与沟通应用，归入 `application`；不因官方使用 Agent 的营销称谓而自动归入 `agent`，也不归入开发者工具。

操作系统使用独立分类 `operating-system`，包括 iOS、macOS、Linux 与 Omarchy；Linux 的摘要明确其内核与系统生态范围。

大会、峰会等具体活动使用 `event` 产品分类。活动主办方是品牌，活动本身是产品；活动不归入媒体与社区品牌。

游戏作品使用独立分类 `game`，例如《吸血鬼幸存者》。游戏引擎与游戏开发工具按工具用途分类，不归入游戏。
影视剧集使用 `series` 分类，例如《黑镜》；不归为应用或图书。
图书作品使用 `book` 分类。小说与同名影视改编需明确条目范围，按节目实际讨论对象收录，不把图书归为应用或游戏。

## 模型、名称与别名

模型家族保留不带版本号的主条目。带版本号、日期或快照后缀的名称，以及这些版本已有的有效别名，归入对应模型家族的 `aliases`，不单独生成产品页。版本名称在逐字稿中保持原文，链接指向模型家族。

Muse Voice Transcribe 归入 Muse 模型家族的别名，不单独生成产品页。

主名称使用正式名称，不额外添加“项目”等分类后缀。Next Token 的完整名称、Next Token 和词元之外指向同一品牌。别名不重复登记中英文正式名称或已有的相同别名。产品页面与结构化数据不展示仅大小写不同的重复名称；逐字稿区分大小写匹配所需的变体可保留在原始别名中。别名只收录确实指向该实体的名称；套餐价格或口头描述不作为别名，Codex 200 不属于 Codex 别名。

含有产品名称的作者描述不作为人物别名，例如“Ruby on Rails 那个连，作者”中仅产品名称建立链接。作者身份由人物与产品的资料关系表达。“豆包办公”属于逐字稿中讨论的误称，不登记为豆包工作的正式别名。

实体使用稳定 ID，引用与页面路径不从展示名称临时推导。实体合并或分类迁移时，分期提及、人物关系和逐字稿链接使用最终实体；导入快照由脚本生成。歧义名称由分期规则明确指定，不靠分类优先级猜测。

## 列表排序

品牌与产品列表按当前页面语言的名称排序。人物列表保留主理人按 `displayOrder` 置顶，其余人物按当前页面语言的姓名排序，同名时以稳定 ID 排序。分类筛选保留原有排序。

## 资料字段

硬件条目既可以表示具体产品，也可以表示明确的产品系列。只泛指“群晖 NAS”“绿联 NAS”时，以该名称收录 `hardware` 产品系列，摘要明确其系列范围，不推断具体型号，不填写统一的盘位、配置或发布日期。没有独立组织内容时无需另建公司条目；已有品牌条目的产品可引用它，例如 Xiaomi 智能存储引用小米。

泛称“NAS”不作为某个厂商系列的别名。只有特定分期语境中，“群晖”“绿联”等厂商简称明确代指 NAS 时，才在该分期的 `scopedAliases` 中关联产品系列，不写成全局产品别名。

条目包含中英文名称与摘要、明确的类型、官方链接和核验日期；事实来源保存于 `sources`。产品状态、发布日期和所属品牌仅在有依据时填写。资料说明记录当前分类规则与事实，不记录讨论或操作过程。

逐字稿中，完整模型版本名称优先匹配并链接到模型家族；产品名称紧邻成对书名号时，书名号与名称一同进入链接。004 不收录灾厄、Git、Bash。

Apple WWDC 与 OpenAI DevDay 同为活动产品，归入 `event`。完整硬件型号和模型版本链接到对应产品家族。

## 分期提及分组

每期的提及列表保留人物、品牌、产品三个大类，各类内部按资料库类型分组。人物使用 `kind` 按主要介绍的身份归入创业者与企业管理者、研究者与工程师、创作者与社区主理人或其他人物；每人只展示一次。人物目录的主理人筛选仍由节目成员关系决定。品牌与产品沿用各自的 `kind`，分类名称与资料库目录共用。空分组不显示，组内保留分期提及顺序。
