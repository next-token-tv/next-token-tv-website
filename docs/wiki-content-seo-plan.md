# Wiki 内容与 SEO 改造方案

基线日期：2026-09-17。本文是后续工作的范围与交付约定；[编辑规范](wiki-editorial-plan.md)约束内容，[技术与验收规范](wiki-technical-implementation-plan.md)约束实现。三份文档描述当前方案，不是改造过程记录。

## 目标与范围

在现有产品、品牌、人物条目上增加有用、可引用、可核验的正文和 FAQ，并保持统一的内容型页面。优先回答读者实际搜索的问题，连接官方资料、相关实体和节目原文。

- 当前扩充对象是现有产品条目；品牌、人物已有样板，后续按明确分配的实体 ID 扩充。
- 暂不增加术语、概念、新主题指南或筛选组合落地页。这些不是当前 Agent 的待实施任务。
- 保留实体 ID、URL 与分类。模型版本归入既有模型家族；品牌类别可描述公司、组织或独立媒体，页面标签统一为“品牌”，不改为“公司”。
- 已完成的共享页面结构直接复用。内容扩写不另建页面模板、不重做视觉方案、不新增讨论摘要数据集合。

## 已确定的页面约定

三类正文页共用返回导航、标题区、阅读区和资料区样式，具体文件与例外见[技术规范](wiki-technical-implementation-plan.md)。

- 返回导航分别为“全部产品／全部品牌／全部人物”；详情页不放目录分类切换。
- 产品／品牌使用黑色身份卡，顶部分类标签 1rem，中间突出领域或产品类型，底部弱化 `Next Token / Wiki` 署名，保留橙色标记。
- 人物使用正方形头像或姓名占位卡，与产品／品牌视觉区域同高，在左栏居中。桌面视觉区高 12rem，窄屏高 9rem。
- 各一级区块分别使用同一级 `.shell`，统一分割线宽度、左右留白和内容栏起点；不在人物页面外再嵌套一个带内边距的整页容器。
- 保留区块分割线，去掉辅助资料内部链接与列表行的装饰线。正文引用链接保留下划线。
- 关联实体使用“条目、人物关系、参考来源”的逐行布局，手机按条目分组；来源显示具体名称或域名。
- “在 Next Token 中出现”使用同一相关节目组件，作为详情主体最后一个模块；无相关节目时不制造空栏目。
- FAQ 位于正文介绍与讨论之后、来源之前：H2 为目录入口，H3 为问题，简短回答直接展开。正文更新与资料核验日期放在侧边目录下方，保持各自含义。

## 内容与搜索策略

每篇正文覆盖准确定位、实际用途、必要的产品区别或限制、官方入口、直接相关的节目讨论、FAQ 和来源。按资料决定章节，不凑字数，不复制统一的安全警告或编辑说明。节目观点必须有归属；产品事实需独立核验。正文介绍保持时间稳定，优先写与阅读时间无关的事实，时效状态的处理口径见[编辑规范](wiki-editorial-plan.md)的"时间稳定性与表述口径"。

FAQ 先有需求线索，再选择可回答的问题。优先考虑官网、下载、安装、登录、API、计费方式及合理产品比较；不是所有产品都套同一组问题。官方文档证明答案，自选查询命中搜索结果不能单独证明问题热门。缺少证据时标记为编辑补充，不能伪装成热词。

## 后续交付单位

按明确实体 ID 分批交付，每批建议 4–6 个产品，包含独立可读的中文与英文正文、来源、FAQ 需求证据和节目引用。这是协作粒度建议，不限制用户另行指定数量，也不把 105 个剩余产品视为一次自动全量任务。

候选顺序依据节目讨论深度、资料充分度、搜索需求线索和维护成本；[编辑规范](wiki-editorial-plan.md)提供下一批候选。仅被提及、缺乏可靠资料的条目暂保留摘要页，不强行扩写。

每批交付须完成内容审阅、静态构建、内链与引用检查、双语页面检查及适用的仓库回归检查。正文存在不等于事实已核验，也不等于页面已上线。

## 效果衡量与发布

有实际数据后，按页面、语言、国家和设备比较同等 28 天窗口的曝光、点击、平均位置与目标查询覆盖率。CTR 用总点击除以总曝光；覆盖率只针对可见目标查询样本，不能把缺失查询视作零需求。新页面先建立基线；页面点击不能直接归因于某条 FAQ，AI 引用效果需独立观测。

当前不创建自动监控任务。提交遵循 Conventional Commits，保留无关工作；提交、推送和部署按实际任务授权执行，不由本方案自动触发。
