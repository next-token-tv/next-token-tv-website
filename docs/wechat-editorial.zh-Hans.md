# 公众号整期对谈精编规范

## 定位

公众号稿件默认采用整期对谈精编：保留一期节目主要话题、具体案例和人物交流感，让读者既能连续阅读，也能按导读选择话题。提升可读性主要依靠组织和节奏，不以大幅删减信息量换取短篇幅。

这与 `/blog` 的单主题分析文章不同。除非用户明确要求，不把整期对谈改成只讨论一个问题的编辑文章，也不强制压缩到固定字数。不是完整逐字稿，可以删节重复、口头填充和无信息的接话。

## 组织

- 标题覆盖本期主要张力与内容，避免堆满产品名，也不以一个支线故事代替整期主题。
- 开头用两三个具体经历或分歧带读者进入，不复述节目成绩、参与者名单和录制流程。
- 相关话题归为若干大组，以 H2 展示；每组内用 H3 保留具体话题。分组数、话题数随材料变化，不固定为五组或十二节。
- 页面提供可跳转的主题导读；正文不重复一份相同目录，不在正文前放整屏节目封面。
- 每节尽快进入场景或有信息的发言。允许调整话题顺序，但保持问答关系和语义上下文，不把不同问题的回答拼成新对话。
- 结尾可停在节目有力量的观点或分歧上，不追加泛泛的趋势展望，也不强行总结成统一结论。

## 发言和署名

保留第一人称、具体操作、个人体验和说话人的表达习惯。长段经历不改成反复的第三人称转述；有信息的追问、反对和玩笑保留，无信息的附和可删。同一人围绕同一问题的零碎发言可合并，但不能跨过分歧，改变回答对象。

人物使用固定 emoji 加姓名的小署名段落，不作为 H3，不单独占大块留白：

| 人物 | 固定署名 |
| --- | --- |
| 杨攀 | 👨‍💻 杨攀 |
| 歸藏 | 🐈 歸藏 |
| 向阳乔木 | 🔥 向阳乔木 |
| 橘子 | 🍊 橘子 |

Markdown 中使用 `<p class="speaker">👨‍💻 杨攀</p>`，与正文间留空行。新嘉宾先核对姓名；没有已确认标记时保留姓名，不猜测 emoji。emoji 是辅助识别，不能代替姓名。

页面标注“发言经删节整理”。整理后的发言不整体加引号，不伪装成逐字引用。需要直接引用的句子必须与原文核对。加粗只用于少量值得停留的表达，不给每位发言人提炼一句新造的“金句”。

## 信息和事实

- 以 `src/content/imported/transcripts/` 中已批准的对应期数文字稿为依据；旧稿只帮助定位，不能代替原文。
- 保留关键细节：做了什么、用了什么、步骤、输入输出、规模、耗时、成本、结果和限制。无需把所有技术名词都展开成教程。
- 核对发言归属，尤其是相邻的短句、玩笑和观点转折；不按旧稿署名直接继承。
- 区分实际做过、正在尝试、设想和推测，不把个人体验写成产品普遍能力，不替人物补充确定性。
- 保留分歧和失败案例，不把节目整理成产品宣传，也不把几个人的说法写成全体共识。
- 不用外部研究覆盖原有对话。确需补充背景时，核验后以明确的编辑注释呈现，不能塞进人物第一人称发言。
- 改稿前保留可恢复的旧版本；未提交原稿不能仅依赖 Git 恢复。

## 排版和验收

主题标题、具体话题、人物署名和正文有清楚层级；署名紧邻发言。移动端保证段落与长英文名称正常换行，导读可以点击，不出现横向溢出。

核对主要话题及案例是否仍在、人物 emoji 是否一致、引语归属是否正确，再查看桌面与手机实际页面。修改复制逻辑时验证复制内容包含 emoji 与姓名；网页内跳转在复制版中不应成为失效锚点。

第 006 期的 `src/content/prose/wechat/006.md` 是整期精编的写法参考，不是固定话题、章节数或篇幅模板。路由、元数据、复制功能与发布边界见 [公众号对话频道](wechat.md)。本地试稿和写法认可不等于发布到网站或微信公众号。
