# Next Token 公众号对谈精编

写作前阅读 [编辑规范](../../../docs/wechat-editorial.zh-Hans.md) 和 [频道契约](../../../docs/wechat.md)。前者是风格规则的唯一来源；不要套用博客的第三人称单主题结构。

## 取材与成稿

1. 读取对应期数已批准的 `src/content/imported/transcripts/` 快照及相关章节完整上下文。改稿时先保留可恢复的旧版本，尤其是未提交内容。
2. 梳理主要话题、具体案例和分歧，再组合成主题分组；信息覆盖用于内部核对，不写成页面上的编辑过程说明。
3. 按规范保留第一人称对谈，合并零碎发言、删去重复接话。使用 H2 主题、H3 话题、带固定 emoji 的轻量人物署名。规则和标记表直接查编辑规范。
4. 写入 `src/content/prose/wechat/NNN.md`，沿用频道元数据与模板。默认整期精编；只有用户明确要求时才改成单主题节选。

## 检查与交付

- 对照原文核对案例条件、数字、归属、分歧与进度；没有材料支持的判断不归给人物。
- 比较修改前后的话题覆盖，避免以缩短篇幅为目标丢失整期内容。第 006 期可作写法参考，不能机械复制其章节数量。
- 运行 `npm run test:article`；改样式时运行 `npm run lint:styles`。这些检查不替代本篇事实审校。
- 本地查看 `/wechat/NNN` 的桌面和手机页面，检查 emoji、小署名、正文层级及导读跳转。若改复制功能，另验证复制 HTML 和纯文本。
- 把试稿打开给用户查看，明确本地、提交和发布状态。写稿或认可风格不授权发布；用户另有发布授权时按授权执行。
