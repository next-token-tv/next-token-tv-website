# Next Token Blog

在网站仓库中使用此技能。编辑风格以 [博客编辑规范](../../../docs/blog-editorial.zh-Hans.md) 为准；字段、路由与发布状态遵守 [博客内容契约](../../../docs/blog.md)。写作或改稿前阅读这两份文档，风格规则只在编辑规范中维护。

## 选材

用户已选定主题时直接执行。未指定时，按读者价值、主题独立性和可行的研究路径选题，不按期数分配固定篇数。节目一句话也可以成为独立文章的起点；按编辑规范延展，不因节目材料少就缩短或舍弃。选题卡分别写明节目切入点、延展问题和研究需求。

以 `src/content/imported/transcripts/` 中已批准且来源已提交的文字稿定位节目线索，读取相关章节的完整上下文；它是节目内容的依据，不是文章唯一的资料来源。旧稿帮助定位，不能代替原文。关键材料保留说话人、原文、条件、进度和出处，以供核对；使用 `src/data/transcript-paragraph-anchors.ts` 生成稳定段落锚点，不猜测 ID。

## 研究与延展

围绕文章的问题列出需要解释、比较或验证的内容，再查找官方文档、原始论文、公开数据、案例或实际项目记录。技术和时效性事实按需联网核实；记录来源、日期与支持的具体说法，不能把待查方向当已证实的发现。

用外部材料和独立分析补足论证，检查反例与适用条件；需要时调整节目中的初步判断。按编辑规范区分节目材料、外部证据、编辑推论和假设示例，不虚构试验，也不把新增观点归给主理人。只有缺乏可行证据路径等实际障碍时才暂缓选题。

## 写作与改稿

以问题的逻辑组织正文，直接展开场景、案例和论证。执行编辑规范中的主题文章视角；避免仅删除人名而保留逐段转述结构。

改稿时先确认每一节在回答什么，再调整材料和段落。保留具体细节与事实边界，来源集中到页面元信息和文末。新增外部事实需要独立核实；跨期材料保留时间差异，不把后来的信息倒写成早期结论。

需要比较写法时，查看编辑规范末尾链接的两篇参考文章，不强制复用其标题、结构或长度。

## 交付检查

- 通读正文：读者能否不认识主理人、不听原节目就理解全文；段落是否依靠问题本身推进。
- 按材料来源分别对照文字稿、外部资料与实际记录，核对数字、引语、案例条件、试验进度和分歧；不把个例写成通则，不把设想写成已发布功能，不虚构作者亲历。
- 检查每篇主题是否独立，与同批文章是否大面积重复；标题和摘要是否准确，正文是否没有重复 H1。 批量选题时按编辑规范检查标题句式，避免整批套用同一种问句或陈述句模板。
- 核对文末节目锚点、外部来源及 Wiki 路径，确认各项关键事实由对应来源支持。运行 `npm run test:article`；程序检查不替代逐项事实审校。
- 写入 `src/content/prose/blog/<slug>.md`，使用 `episodes` 关联提供话题线索或材料的节目；外部来源在正文或文末引用，不伪造节目归属。检查本地 HTML 和 Markdown 呈现。涉及模板或状态逻辑时，再运行相应构建与页面检查。

试稿默认 draft；风格认可不自动改变发布状态。已授权的发布按授权执行，写稿不隐含推送或部署授权。
